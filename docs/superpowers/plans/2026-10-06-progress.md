# Ledger V1 annonces en situation

## Arbitrages appliqués

- GO plan + code confirmé, implémenteur unique, pas de sous-agents, commit, push, déploiement ni migration production.
- Le brief utilisateur prime sur les réserves du plan: feuilles villes acceptées si la colonne Plateforme est univoque, nouvelles feuilles plateforme prioritaires, conflit explicite.
- Manifeste: référence + ratio, partagé entre image et capture vidéo; destination conserve son type. Noms multi-ratio, collisions normalisées de références distinctes et doublons de fichiers demandent un choix manuel.
- Stories: image/vidéo explicite, Reel vidéo. Ajout 16:9. Format historique conservé, NULL pour nouvelles annonces YouTube en DB.
- Photo n crée une carte, Fiche n contient son titre puis sa description; Titre n / Description n prennent priorité. Pas de carte créée par une Fiche vide.
- Fichier réel présent dans Downloads: 18 annonces Facebook, deux notices de compatibilité des feuilles villes. La fixture synthétique contient 12 annonces et ne prétend pas reproduire les textes privés.
- Specs issues de l'inventaire local: limites dures distinctes des seuils d'affichage; valeurs non confirmées exposées null. Stories Instagram: marge basse 35%. Les mockups nécessitent une revue visuelle utilisateur pour confirmer leur fidélité.

## Implémentation

- Quatre modules purs et tests: specs + conversion legacy, import XLSX, manifeste, export.
- Paramétrage par utilisateur, logo signé; création manuelle et RPC d'import appliquent les défauts sans propagation rétroactive.
- Import aperçu + rapport puis création transactionnelle auth.uid(), export owner-only des textes actuels.
- Uploads images 50 Mo, signature owner-validée, rattachement recalculant les destinations du manifeste; politique list/insert/update/delete restreinte aux chemins du propriétaire dans social-ads.
- Review groupée dans l'ordre de première apparition, navigation, compteurs par annonce avec priorité révision, édition publique limitée aux cinq champs, commentaires et décisions avec erreurs visibles.
- Invalidation DB des décisions lors d'édition des textes, marque, visuels ou variante; statut recalculé avec priorité révision.
- Mockups fixes: Feed Facebook/Instagram/LinkedIn, Stories/Reels, TikTok, YouTube In-stream/In-feed/Shorts. Aucun lecteur vidéo ni durée inventée.
- Tailwind theme/utilities seulement, aucun preflight; CSS existant conservé. ESLint remplace next lint. turbopack.root explicite.
